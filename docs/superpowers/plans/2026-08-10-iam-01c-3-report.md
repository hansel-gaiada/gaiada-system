comment away later without a red test stopping them.

## 2. Test written

**File:** `platform-nest/src/admin/assign-role-global-scope-idempotent.test.ts` (new, only file this
ticket owns besides this report).

Two tests, both driving the real HTTP endpoint via `app.inject` (the layer the regression actually
lived in — the DB-level `user-roles-global-scope-uniq.test.ts` from IAM-01c-2 proves the index and
`grantRole()` idempotency but does not exercise `assignRole`'s own `ON CONFLICT` clause at all):

1. **`re-granting an already-held GLOBAL role returns the SAME grantId twice and never 500s`** —
   `POST /api/:tenantId/users/:userId/roles` with `{ roleId, scopeType: "global" }` (no `scopeId`,
   so the handler sets it to `NULL`) called twice for the same user+role. Asserts both calls return
   201, both return the identical `grantId`, and a direct `withGlobal` query afterward shows exactly
   one row in `user_roles` for `(user, role, 'global', NULL)`. This is the exact call shape that
   only reaches the new partial index and never the old 4-column constraint (NULL `scope_id`), so a
   pass here is not obtainable by accident on the old (pre-0092) constraint alone once the partial
   index exists and a targeted arbiter is named against the wrong one.

2. **`re-granting an already-held COMPANY-scope role (real, non-NULL scopeId) is unaffected`** — same
   shape but `scopeType: "company"`, `scopeId: tenantA` (a real, non-NULL value). Proves the ticket's
   point 3: the case the *original* targeted `ON CONFLICT` clause always handled correctly must keep
   working under the untargeted clause too. Both calls 201, same `grantId`, one row.

Neither test touches `managed_by`. Both grants in this file are fresh manual admin grants against
users with no `service_assignments` in play, so `managed_by` stays NULL throughout — this file makes
no assertion about it and does not intersect `managed-by-invariant.test.ts`'s adoption-path
invariant. Read that file first, as instructed; no conflict found, nothing here needed adjustment.
