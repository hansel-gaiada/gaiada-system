## 1. Reconciliation decisions (R-1..R-7; Web Dev wins ties per owner)

- **R-1 — Two Homes, one data spine.** No conflict of place: WS-UX's role-differentiated Home
  lives at app `/` (cross-company, personal+managerial); the Web Dev command-center Home lives at
  the department console (team workspace). BOTH ship. But there is ONE "what needs me" model:
  `getMyWorkQueue` (WSUX-5) becomes the shared data source; the console's `MyWorkRail` renders a
  compact, dept-scoped projection of the SAME QueueItem set (rail component is props-only, so
  this is a data-wiring change, not a component change). No second queue implementation may exist.
- **R-2 — Department workspace: the console IA WINS; the focus model GRAFTS IN.** Daily-work
  spec §3's single-page dept workspace (FocusControl + HealthStrip + swimlane Board on one page)
  is **superseded** by the built tabbed console (dept-console-design §2, decision #10). What
  survives from §3: the **focus model** (Whole dept / Division / Just me — the ORG-CORE STEP-5
  semantics) and the **Board swimlane-by (Status/Division/Person)**, grafted into the console's
  Board tab; ServicedBlock (already on console Home); division params validated against org
  units. **DROPPED:** HealthStrip (KpiStrip supersedes), the §3 page rewrite. This is recorded as
  a spec amendment: `2026-07-20-daily-work-ux-spec.md` §3 is superseded by
  `2026-07-22-dept-console-design.md` + this section.
- **R-3 — Rail "Waiting on me" repoints to the unified approvals read.** P1-07 wired the rail to
  per-origin reads (`lib/automationApprovals.ts` + agency pending). Once WSUX-1 is live, the rail
  and any console approvals surface consume `GET /api/approvals` (scoped to the dept's company)
  so urgency/decidability semantics are identical app-wide. The per-origin libs stay as fallback
  until then (graceful-degrade convention).
- **R-4 — Everything app-level from WS-UX v1 KEEPS:** unified approvals read/decide façade
  (WSUX-1/2), tasks/mine union shim (WSUX-3, D-UX-1 verdict unchanged), typed notification
  payloads (WSUX-4/9), app Home (WSUX-5), unified inbox (WSUX-6), tasks/calendar scope deltas
  (WSUX-8), fixtures/design-QA/security-gate/regression (WSUX-10..13). The Web Dev plan has no
  competing design for any of these.
- **R-5 — Everything foundation-level from Web Dev ADOPTS:** F2 activity consumer (make the
  built feed LIVE), F1 connections subsystem (opus·medium tag carried — encrypted-credential
  vault + own-vs-company authz that Phase-2 tokens ride on), Connections UI, C1 seat registry.
  Migration renumber: `0031_integration_connections.sql` → **`0033_integration_connections.sql`**.
- **R-6 — QA merges.** P1-11's checks fold into WSUX-12 (security half: cross-tenant RLS probes
  on `work_activity`/`work_activity_links`/`integration_connections`, token non-exposure sweep,
  Cerbos own-vs-company matrix) and WSUX-13 (functional half: full console tab walk incl. rail,
  DEMO_MODE + live).
- **R-7 — Locked Web Dev decisions carry forward verbatim** (phase1-tickets "Locked design
  decisions" #1–13): connections are per-company (owner-resolved), C1 = seat-identity display,
  Build-Tools-into-Home, F2 in core not a module, token crypto shape, KPI semantics #12. None
  conflict with backbone/ORG-CORE rules. One tension re-flagged to the owner in §5 (per-company
  connection links vs shared-service staff, now that shared services are LIVE).

Carried unchanged from v1: **D-UX-1** (tasks/mine union shim; WS-B stays separate), **D-UX-2**
(per-tenant legs, never a widened GUC set), **D-UX-3** (TaskRow `source`+`href`; one canonical
urgency table), **D-UX-4** (`isManagerTier` without holding_head), **D-UX-5** (Envelope/ScopePill
