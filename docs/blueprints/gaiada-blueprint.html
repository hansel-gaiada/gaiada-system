§00

Executive Summary

What the platform is, where it stands today, and how the new WebDesk website platform fits in.

The Gaiada AI Platform consolidates every company in the group — digital agency, resort, marine, printing, and more — onto one modular, multi-tenant system with a single interface to track all work, and with AI woven through every layer to augment every employee. It is delivered as a pragmatic Solo-Viable v1 (managed-first, cloud-AI-first, single-region) beneath a preserved, hiring-gated all-local Target-State that remains the north star.

Architecturally it is a layered platform, not a single app: a NestJS platform core is the source of truth; an MCP Hub exposes its data and tools to AI and surfaces; a Go AI Gateway is the single secured egress for all model calls; an agent brigade, automation engine, and a family of surfaces (WhatsApp/Telegram bot, ERP web UI, department consoles) sit on top. Each component is a separate standalone deployable, not a monorepo package — so each is built, run, and scaled independently.

Most of the spine is prototyped — running in the dev stack — and in several cases dev-verified end-to-end on a live local stack, but none of it is in production: the platform core with RBAC and the agency vertical, the event backbone, the Go gateway, the MCP hub, the cross-site sync engine, the observability stack, the automation glue, and a functionally complete ERP UI (in dev) including per-department consoles. What remains is the admin/systems API layer, further verticals, deeper AI-agent capabilities, production deployment, and the target-state infrastructure.

How to read status in this documentNothing here is production-finished. Statuses use one vocabulary: PLANNED (design only) · IN PROGRESS (partial) · PROTOTYPED (works in dev, not production) · DEV-VERIFIED (prototyped + exercised end-to-end on the local stack). "Built/done/complete" is deliberately avoided. Per-module versions, status, and future plans live in the authoritative docs/modules/MODULES.md registry and docs/modules/CHANGELOG.md.
New in this blueprint — WebDeskThe Web Dev department is adding WebDesk, a centralized multi-tenant website backend (CMS + forms + mail) that serves all client websites through one uniform contract. It is a new trust zone attached to this platform: internet-facing, physically separated, and controlled by the ERP. It is PLANNED (blueprint only, v0.0.0). §12 details how it connects; its full engineering spec is a companion blueprint.
§01

Vision & Operating Model

Vision

Migrate Gaiada to AI-assisted operation: enhance every employee's output and consolidate all projects and tasks into one digital platform with a single interface. AI augments people; the custom platform is the source of truth; the MCP hub exposes company data and tools to AI and every surface.

Guiding principles

P1 · Local-first, cloud-failover

Production processing on Gaiada's own servers; paid cloud AI only as automatic, capped, alerted failover.

P2 · One source of truth

Each capability owned by one layer — no logic duplicated across services.

P3 · Ship small first

Usable tools shipped early for value + discovery while the platform is built in parallel.

P4 · Swappable everything

LLM providers, WhatsApp gateway, data adapters, storage — all behind interfaces.

P5 · Zero-trust by default

mTLS mesh, no public listeners, RBAC + RLS, OBO everywhere, immutable audit.

P6 · Separate deployables

Components are standalone projects, independently built/run/scaled — not a monorepo.

The layer contract (prevents duplicated logic)

  • MCP = access. Exposes data/tools as nouns & verbs; one authoritative interface per capability.
  • Automation (n8n) = orchestration. Sequences/schedules by calling MCP tools; no business logic lives in workflows.
  • Custom services = logic. The platform core owns business rules and the data model.
  • Gateway = AI egress. Every model call exits through one secured, DLP-enforced chokepoint.

§02

System Overview

The whole estate on one plate — surfaces, the AI layer, the platform core, data, cross-cutting planes, and the adjacent WebDesk zone.

  • Surfaces never assert identity and never hold provider keys — they call the hub/gateway with OBO tokens.
  • The AI layer is split by responsibility: MCP = access, Gateway = egress, agents = reasoning, Hermes = a local-model shim into the gateway contract.
  • The platform core is the single source of truth; the sync engine reconciles it across sites.
  • Cross-cutting planes (identity, authz, observability, delivery, automation) serve every component.
  • WebDesk is an adjacent, internet-facing zone controlled by the core — detailed in §12.

§05

Data, Tenancy & Sync

One shared database, hard per-tenant isolation, module-driven heterogeneity, and an event log that doubles as the sync spine.

Multi-tenancy & modules

  • Shared DB + FORCE RLS on an authorized-tenant-set (D5) — every query is tenant-scoped; the app role is NOBYPASSRLS.
  • Heterogeneity via compile-time modules + custom fields (D17) — verticals extend the core through the ModuleContract framework and a per-tenant enable gate, not schema forks.
  • Per-service DB roles — owner/migrator + per-service runtime roles; a hard platform↔sync grant boundary; Keycloak/n8n on Postgres; isolated bot Postgres; split Redis.

Event backbone & sync

A transactional outbox is relayed to Redis Streams and consumed with dead-lettering; the same outbox_events log is the sync spine. platform-nest stamps a Hybrid Logical Clock on every emit, and the Go sync engine reconciles across sites with per-field conflict rules and a dedup ledger that never touches the relay's own state (D7).

HA ≠ backupStreaming replication provides availability; durability comes from immutable/WORM backups + PITR and rehearsed restores (§10). Crypto-shred (two-axis subject×entity) makes PII erasure real.
§06

Identity, RBAC & Zero-Trust

Authentication and authorization are split and both authoritative: Keycloak (OIDC) proves who you are; Cerbos decides what you may do; RLS enforces which rows you touch. No surface asserts identity — everything acts on-behalf-of a minted principal.

AuthN

Keycloak OIDC (JWKS verify, auto-provision, email-verified takeover guard). Hybrid: SSO + dev-login coexist; UI uses PKCE.

AuthZ

Cerbos versioned policy repo — scope-cascade derived roles, PlanResources, team scope, decision audit, D11 revocation.

Isolation

Postgres FORCE RLS on every table; per-service runtime roles; OBO principal minting at the hub.

Mesh

Self-signed internal CA + mTLS between gateway/hub/sync; peer-CN allowlists; no public listeners on datastores.

Enrollment

D4 dual-proof identity_links (WA/TG ↔ platform user), step-up ceilings for sensitive skills.

UI RBAC

lib/rbac.ts capability model + company switcher; nav + write actions gated (Cerbos/RLS remain authoritative).

§07

AI Layer

Four responsibilities, four owners — so no layer duplicates another.

  • Gateway (WS3) — the only path to any model; DLP, cost cap, failover, egress audit.
  • MCP Hub (WS2) — the only path to company data/tools; OBO + Cerbos + audit.
  • Agents (WS8) — reasoning/orchestration over hub tools, budget- and safety-bounded.
  • Local inference — Ollama/llama.cpp + Hermes via the gateway contract; cloud is capped failover. The whole stack can run offline.

§10

Observability & Delivery

Observability (WS9)

All services carry OpenTelemetry (traces + metrics + trace-correlated logs, W3C propagation, fail-soft — no-op unless OTEL_ENABLED). An opt-in self-hosted stack — OTel Collector → Prometheus/Tempo/Loki + Grafana + Alertmanager + exporters — provides exec + per-workstream dashboards, multi-burn-rate SLOs, blackbox synthetics, ≥2 independent alert transports, and a measured restore drill. Dev-verified end-to-end on a live local stack (not yet deployed to production).

Delivery (WS10)

A supply-chain-secure release pipeline (SBOM + cosign + SLSA), per-component Dockerfiles, a full VPS Compose stack, local CI (test-all.sh), and crypto-shred-safe nightly backups. Kubernetes/GitOps and SPIFFE/SPIRE workload identity are the hiring-gated target-state.

WebDesk — Website Platform

How the new centralized client-website backend relates to this platform.

WebDesk is the Web Dev department's centralized, multi-tenant website backend — one CMS + forms + mail platform that all client sites (WordPress, Astro, Node) consume through a uniform, versioned contract, so frontend engineers build only frontends. It is not part of the ERP core; it is a separate, internet-facing trust zone (Zone B) attached to the platform (Zone A).
